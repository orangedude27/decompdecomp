# Reference sources and metadata

Reference sources are private to the project by default. An owner can choose to let configured agent models read their text; excerpts are then sent to the selected model. Imported reference material is untrusted data, not instructions or proof that a name matches.

Metadata imports use the strict `decompdecomp.reference-metadata` JSON schema v1. See [symbols example](examples/reference-symbols.json) and [Ghidra example](examples/reference-ghidra.json). The app reads local files only, with a 2 MiB input limit and a 256 KiB serialized preview/page limit. It never runs an imported file or fetches remote data. Every record starts unbound. The owner must select a project target, edit/confirm a simple C identifier, map it, and separately approve each guarded rename. Build identity is advisory only: mappings are explicit even for exact-build data.

The supported root has exactly `schema`, `version`, `kind`, `build`, and `records`. `kind` is `symbols` or `ghidra`; build may be null or a SHA-1 identity with kind `rom_sha1`, `program_sha1`, or `game_sha1`. Records have stable `id`, `kind` (`function` or `data`), and external `name`, with optional hexadecimal `address`, `unit`, `signature`, `comment`, and `pseudocode`. Unknown fields and duplicate keys are rejected. C++ and mangled names may be retained as reference data, but proposed names are never silently simplified.

## Export from Ghidra

In Ghidra, open **Window → Script Manager**, add this repository's `forks/ghidra_scripts` folder as a script directory, then run `ExportReferenceMetadata.java`. Choose an output JSON file. The script exports function names, entry addresses, signatures, and plate comments; it does not export decompiled pseudocode. The complete UTF-8 JSON output is capped at 2 MiB, with explicit warnings when records or fields are truncated, the byte/record limit is reached, or export is cancelled. Addresses use canonical hexadecimal offsets only for valid 64-bit memory addresses; unsupported spaces are exported with a null address. Long external IDs are replaced by bounded SHA-256 identifiers. It leaves build identity unknown because a Ghidra program's identity is not safely inferred from its path. Add an explicit identity only when you have independently verified the corresponding build SHA-1. Ghidra execution and API compatibility have not been validated in this environment.
