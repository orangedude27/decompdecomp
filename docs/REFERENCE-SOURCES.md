# Reference sources and metadata

Reference sources are private to the project by default. An owner can choose to let configured agent models read their text; excerpts are then sent to the selected model. Imported reference material is untrusted data, not instructions or proof that a name matches.

Metadata imports use the strict `decompdecomp.reference-metadata` JSON schema v1. See [symbols example](examples/reference-symbols.json) and [Ghidra example](examples/reference-ghidra.json). The app reads local files only, with a 2 MiB input limit and a 256 KiB serialized preview/page limit. It never runs an imported file or fetches remote data. Every record starts unbound. The owner must select a project target, edit/confirm a simple C identifier, map it, and separately approve each guarded rename. Build identity is advisory only: mappings are explicit even for exact-build data.

The supported root has exactly `schema`, `version`, `kind`, `build`, and `records`. `kind` is `symbols` or `ghidra`; build may be null or a SHA-1 identity with kind `rom_sha1`, `program_sha1`, or `game_sha1`. Records have stable `id`, `kind` (`function` or `data`), and external `name`, with optional hexadecimal `address`, `unit`, `signature`, `comment`, and `pseudocode`. Unknown fields and duplicate keys are rejected. C++ and mangled names may be retained as reference data, but proposed names are never silently simplified.

## Export from Ghidra

In Ghidra, open **Window → Script Manager**, add this repository's `forks/ghidra_scripts` folder as a script directory, then run `ExportReferenceMetadata.java`. Choose an output JSON file. The script exports function names, entry addresses, signatures, and plate comments; it does not export decompiled pseudocode. The complete UTF-8 JSON output is capped at 2 MiB, with explicit warnings when records or fields are truncated, the byte/record limit is reached, or export is cancelled. Addresses use canonical hexadecimal offsets only for valid 64-bit memory addresses; unsupported spaces are exported with a null address. Long external IDs are replaced by bounded SHA-256 identifiers. It leaves build identity unknown because a Ghidra program's identity is not safely inferred from its path. Add an explicit identity only when you have independently verified the corresponding build SHA-1. Ghidra execution and API compatibility have not been validated in this environment.

## Prepare and explicitly try one candidate

Select an enabled, fresh indexed file or full metadata pseudocode record and an existing target **function**. Shared-room hosts and guests are unsupported. Preparation is a source-only preview: no compiler, subprocess, progress synchronization, claim, agent, attempt, database record, or project-file write. Reference text comes only from the private indexed snapshot, not a fresh read of the reference directory. Model retrieval permission remains independent of owner compilation consent.

Choose an unambiguous complete function by name, a complete line range, or a manually edited definition. Duplicate/overloaded names and assembly stubs are refused rather than guessed. Conservative extraction does not reconstruct namespace/class wrappers, operators, macro-generated definitions, K&R parameters, or constructor initializer lists; select/simplify the definition manually when possible. Identifier mappings act simultaneously outside comments, strings and C++ raw literals. A target alias must match explicitly; preparation never renames a constructor or project symbol. Move reviewed declarations into Prelude. No SDK types, field layouts, headers or M2C macros are inferred or imported. M2C placeholders still require manual review. Assembly shortcuts in either field are ineligible. Computed includes and token-pasting macros in submitted code require manual simplification; preview does not run a preprocessor to guess their meaning.

Plans bind the exact reviewed code, reference snapshot, actual target identity, original target bytes/relocations, and existing compiler context. ROM plans bind the effective unit header and configured compiler/range flags. Project plans bind the actual assigned source/unit/object, unit options/mappings, configuration, source/header/harness files and existing build rules. The project-owned compiler flags are defined by those bound rules, **not inferred or overridden from the reference**; a human-readable compiler/version may not be available without executing the build. Missing source coverage, original objects or build setup must be supplied through the normal project workflow, not generated by preparation.

Context scanning uses raw bytes, not mtime caches, with limits of 4,000 relevant files, 20,000 enumerated entries, 64 MiB aggregate and 16 MiB per file. Symlinks, special files and out-of-tree inputs are unsupported. Managed VCS/app/virtual-environment/package-cache directories are excluded; toolchain SDK/runtime identity remains the existing project's trusted profile. This is a conservative snapshot of project inputs, not a hermetic build sandbox: unrelated scanned source/header/config edits can invalidate a plan, and app locks/fingerprints cannot eliminate external editor or environment races. Actual core unit facts are checked again to reject stale cached unit mappings before building or writing.

An in-memory signed plan expires after ten minutes **before admission**; restart invalidates it. Editing any input requires reprepare and fresh consent. **Try and accept if verified** runs the existing trusted project build and normal compiler/linker/objdiff/literal/regression/full-rebuild judge. It does not run reference build scripts. An admitted synchronous trial is not cancelled by closing or changing panels. Only the normal exact verdict can accept code; 100% similarity alone is not identity or acceptance. A miss restores the pretrial source bytes; detected external edits are preserved, not overwritten by stale rollback.

Consent explicitly allows the selected code/Prelude to become ordinary attempts, best or matched source, and normal project commits, accessible to project agents/progress/exports even when broad model access to the reference source is off. Other reference text and private history remain private. Removing a reference/history does not undo already accepted code. Review bounded owner history after navigation or an interrupted response; do not blindly repeat a trial. Unavailable real-game, proprietary-compiler and native-platform validation must not be mistaken for a verified integration.
